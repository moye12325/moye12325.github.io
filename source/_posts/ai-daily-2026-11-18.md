### [编码智能体改用“外置沙箱”：三个实现，共用一套本地 API](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/) ⭐️ 7.0/10

Simon Willison 与 AI 研究实验室 Prime Radiant 合作，提出“外置沙箱（external sandbox）”模式：智能体本身留在沙箱之外，由它执行的代码则被放进独立的沙箱中运行。目的是更安全地试用本地模型，降低误操作或提示注入导致机器被破坏的风险。配套发布了三个沙箱服务器实现：external-sandbox-v86 用 Node.js 服务器借助 v86 在 WebAssembly 中运行 Alpine Linux；external-sandbox-container 是 Python Web 服务器，在 Apple Containers 实例里跑 Alpine Linux；external-sandbox-quicksand 同样是 Python Web 服务器，使用微软的 Quicksand 库，把 QEMU 和 Alpine Linux 一起打包进 Python 包。三者对外提供相同的 localhost API，可配置 Pi、Claude Code 或 Codex，在需要执行代码时把调用发到该沙箱。三者还都带有可选的 HTTP/HTTPS 允许列表代理，用于限定智能体代码可访问的主机，并提供凭据替换机制，让智能体在不持有密钥的情况下发起带认证的 API 调用。原文未给出性能基准、资源开销或与旧做法的量化对比。

rss · Simon Willison · 11月17日 22:52

**「怎么用」** 这条思路的接入方式是：先按自己的平台从三个实现里选一个，启动本地沙箱服务器，再把 Pi、Claude Code 或 Codex 中执行代码的路径指向它的 localhost API；之后可按需在运行中通过网页界面配置允许列表代理，并用凭据替换来代理需要认证的请求。可参考的选型线索是：想要纯 WebAssembly、无需虚拟化支持可选 v86 版；在 macOS 上偏好 Apple Containers 可选 container 版；希望 QEMU 与 Alpine 随 Python 包一起安装、依赖最少可选 Quicksand 版。原文在给出这些内容后被截断，未提供具体安装命令、API 定义和代理配置细节，首次尝试需要以各仓库的 README 为准。

### [Java4Shell：OpenJDK Base64 处理中的远程代码执行](https://calif.io/java4shell/) ⭐️ 8.0/10

一份技术报告描述了被称作 Java4Shell 的 OpenJDK 远程代码执行问题，触发路径涉及 Base64 处理，并需要通过网络进行堆布局操控（“Remote Heap Feng Shui”）。评论中引述的报告内容称，其测试曾在公网 IP 环境中实施，但该攻击对 RTT 和抖动敏感，低且稳定的往返时延更有利于提高利用可靠性。由于利用条件具体，受影响的是满足这些条件的 OpenJDK 部署，而非所有 Java 主机；现有材料未给出受影响版本或修复信息。

hackernews · werrett · 11月17日 21:11 · [社区讨论](https://news.ycombinator.com/item?id=50538240)

**「背景」** Java 4 Shell（CVE-2026-114938）是 OpenJDK Base64 解码器中的一处内存破坏漏洞，由 Calif 发现并上报，其命名明显在呼应 Log4Shell。据 Cyber Kendra 报道，Calif 利用该缺陷在未登录的情况下接管了 Jira、Confluence、Jenkins 和 Keycloak 服务器，Oracle 与 OpenJDK 项目随后发布了修复。The Hacker News 在报道时则称该 OpenJDK RCE 报告尚未得到确认、漏洞细节已经外泄，因此实际受影响的 Java 版本与补丁覆盖范围仍需以官方公告为准。

**「影响」** 使用 OpenJDK 17.0.6 及更高版本、并会解析不可信 Base64 数据的服务，应按 CVE-2026-114938 的修复状态尽快升级。外部报道称该漏洞无需凭据即可经网络触发，CVSS 4.0 评分为 9.2，因此暴露在公网且会走到相关解码路径的应用应优先排查并限制此类输入。

**「社区讨论」** 评论者一方面称赞这项研究的质量，另一方面强调利用条件虽具体、受影响主机仍可能很多；Semgrep 的 ievans 表示已发布免费检测脚本，并列出 HotSpot、Oracle JDK 和 GraalVM JDK 等条件。AgentME 则转述 Twitter 上尚未确认的说法，称问题与 Base64 解码的 AVX-512 实现有关，并可用 -XX:UseAVX=2 作为规避选项。

### [Quad9 退出法国，Cloudflare 警示 DNS 监管风险](https://blog.cloudflare.com/quad9-withdrawal-from-france/) ⭐️ 7.0/10

Quad9 已从法国撤出，法国用户和依赖该解析器的组织需要改用其他 DNS 服务。Cloudflare 在分析文章中把这一退出视为 DNS 基础设施的监管警示，核心问题是解析器是否要因内容屏蔽义务承担法律责任。文章属于政策风险与先例讨论，不是 Cloudflare 发布新技术能力或具体应对措施的公告。

hackernews · subset · 11月17日 22:13 · [社区讨论](https://news.ycombinator.com/item?id=50538994)

**「背景」** DNS 解析器负责把域名转换成 IP 地址，是用户访问网站前的必经环节；因此，一旦监管机构要求屏蔽某些内容，这种要求就会直接落到解析服务运营方身上，而不再只针对网站本身。Quad9 是提供公共 DNS 解析服务的运营方，在围绕解析器责任与内容屏蔽的争议中退出了法国市场，当地用户因此失去这一解析选项。

**「影响」** 对法国用户和机构而言，直接后果是 DNS 解析配置需要迁移到其他公共解析器；对 DNS 运营者而言，这一案例显示内容屏蔽义务可能演变为是否继续在特定司法辖区提供服务的法律与商业风险。

**「社区讨论」** Quad9 CTO johnhtodd 在评论中称，IETF 127 现场对其立场迄今获得 100% 支持，并称同行对 DNS 面临的监管压力普遍感到担忧。driverdan 则批评 Cloudflare 文章未作出具体承诺，并追问 Cloudflare 是否会在类似判决不利时也退出受影响国家；这些是评论者观点，不是已证实的事实。
