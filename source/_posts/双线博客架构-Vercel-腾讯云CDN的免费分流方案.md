## 为什么要折腾架构

我的博客（Hexo + GitHub Pages）长期面临一个经典矛盾：**国外访问快、国内访问慢**。

- 直接用 GitHub Pages：国内直连延迟上千毫秒，基本不可用
- 全托管到 Cloudflare：免费版国内回源绕美国，部分资源反而更慢
- 全走 Vercel：国外体验很好，但国内 TTFB（首字延迟）实测 1.5 秒左右

我用 [tcptest.cn](https://www.tcptest.cn) 测出自己的域名全国平均延迟上千 ms，终于下定决心重构。

## 最终架构

```
                        用户访问 www.kanes.top
                                │
                ┌───────── 阿里云 DNS（免费版）─────────┐
                │                                      │
        运营商线路（电信/联通/移动）              默认线路
                │                                      │
                ▼                                      ▼
        腾讯云 CDN（国内节点）                   Vercel（全球边缘）
        实测 TTFB ≈ 0.5s                        国外用户体验不变
                │ 缓存 miss 时回源
                ▼
        GitHub Pages（moye12325.github.io）
                ▲
                │ push main 触发
        Hexo 构建（GitHub Actions）
```

**核心思路：利用阿里云免费版 DNS 支持运营商线路解析**（默认线路 + 电信/联通/移动三条线路），把国内三大运营商的流量导到国内 CDN，其余流量走 Vercel。国内用户零感知切换，国外用户完全不受影响。

## 关键设计决策

### 1. 回源源站选 GitHub Pages 而不是 Vercel

腾讯云 CDN 回源直接指向 `moye12325.github.io`：

- GitHub Pages 就是为被 CDN 回源设计的，稳定
- Vercel 做回源源站有隐患：免费版对非浏览器 UA（CDN 回源请求）可能触发防护，还白白消耗 Vercel 带宽额度
- 反正每次 push 都会同时部署到两边，内容永远一致

### 2. 缓存策略：根治"国内看到旧内容"

我之前砍掉腾讯 CDN 的直接原因就是**国内看到的博客不是最新的**。这次重构找到了真正的根因：

> 我的文章 URL 是 `/2026/09/09/标题/` 这种**无后缀目录形式**，而 CDN 旧配置的兜底规则是"全部缓存 30 天"——文章页全部落进 30 天缓存，发布新文章后国内用户半个月看到的还是旧版。

修复后的缓存规则：

| 内容类型 | 缓存时间 | 理由 |
|---|---|---|
| 文章页（`/2022`~`/2027` 目录） | 5 分钟 | 新文章 5 分钟内全网可见 |
| 首页/列表页/标签页 | 5 分钟 | 同上 |
| js/css（文件名带哈希） | 7 天 | 内容变了文件名就变，可以放心长缓存 |
| 图片/字体 | 30 天 | 不可变资源 |
| feed/sitemap | 1 小时 | 平衡及时性和回源压力 |
| 兜底 | 10 分钟 | |

**一个细节**：回源配置里的 `ServerName`（回源 Host）必须设成源站域名而不是加速域名——我这里曾配错成 `www.kanes.top`，导致回源 GitHub 时 404，排查了好一会儿。

### 3. DNS 免费版的边界

阿里云 DNS **免费版不支持"境外线路"**（那是付费版功能），但**支持运营商线路**。由于国内用户基本都在三大运营商网络上，运营商分流的效果 ≈ 地域分流，不需要花每月十几块钱升级 DNS。

这是整个方案零月费的关键。

## 效果

| 指标 | 切换前（纯 Vercel） | 切换后（国内走腾讯 CDN） |
|---|---|---|
| 首页 TTFB（国内） | ~1.5s | **~0.5s**（缓存命中时 0.08s） |
| 国外访问 | 不变 | 不变（还是 Vercel） |
| 月费 | ¥0 | ¥0（消耗已购的 CDN 流量包） |

## AI Agent 在这件事里的角色

这次重构里，AI Agent（我用的 [Hermes Agent](https://hermes-agent.nousresearch.com/)）不只是问答工具，而是**全程动手的操作者**：

- 实测各家延迟（Vercel 1.5s / 七牛 0.47s / GitHub 8.9s），用数据支撑决策
- 直接调阿里云 DNS API 加分流记录、调腾讯云 CDN API 配缓存规则——这些原本要在三个控制台点半天的操作，变成了一次对话
- 排查回源 404、定位缓存规则冲突，靠的是它边查 API 文档边二分测试

传统的运维知识 + Agent 的执行力，一个人就能维护一套以前需要"运维同学"才能搞定的架构。这也是我后续文章要展开的话题。

## 总结

1. **免费方案的天花板比想象中高**：免费 DNS 运营商分流 + 已购流量包 + Vercel 免费额度，双线架构零月费
2. **CDN"内容不新鲜"几乎都是缓存规则问题**，不是 CDN 本身的问题；无后缀 URL 的站点尤其要小心兜底规则
3. **可回滚设计**：所有改动都是 DNS 记录层面的，Vercel 项目保留着，随时一条记录禁用就切回去
