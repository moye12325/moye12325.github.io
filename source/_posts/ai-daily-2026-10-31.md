### [并行跑 coding agent：先隔离机器，再谈代码](https://www.reddit.com/r/ChatGPTCoding/comments/1xjf5zb/running_coding_agents_in_parallel_how_do_you_stop/) ⭐️ 6.0/10

这是一篇来自 r/ChatGPTCoding 的经验帖，作者在 Apple Silicon Mac 上同时运行多个 Codex worker，结论是并行 agent 出问题多半不在代码质量，而在共享资源：有人跑 5 个以上会话时，一个 agent 关掉了另一个正在用的模拟器；分开的文件夹并不能隔离共用的工具、浏览器和缓存。作者指出 git worktree 只保护仓库、不保护整台机器，且会不断堆积，有人在自己的 Mac 上发现过 47GB 的旧 worktree。他的做法是给每个 worker 一个独立 Linux 容器，只挂载该 worker 的工作区，不带 home 目录，浏览器与登录也各自独立，成果需主动保存才落到 Mac 上。验收标准是真实输出，例如最近一次任务返回的是实际测试结果：6 个测试通过、exit 0、55 秒。作者也说明限制：这只是单台 Apple Silicon Mac 上的经验，容器是强边界而非保证，且不解决磁盘占用，仅环境本身就要约 700MB 下载。帖子没有给出具体工具、配置、基准或成本对比。

rss · r/ChatGPTCoding · 10月30日 13:18

**「怎么用」** 如果你已经在同一台机器上并行跑多个 agent，并遇到过互相抢占模拟器、浏览器或缓存的情况，可以优先考虑“一 worker 一容器、只挂载工作区、不挂 home”的隔离方式，并把“任务完成”定义为可核对的实际输出（如测试通过数、退出码、耗时），而不是 agent 自己声称完成。需要注意的是，帖子只给了思路，没有给容器方案、编排方式或清理规则；作者本人也在向评论者征集任务结束后的删除与清理做法，因此照做前还需自行确定用哪套容器工具、如何回收镜像与工作区。

hackernews · _chall · 10月30日 07:09 · [社区讨论](https://news.ycombinator.com/item?id=50300683)

**「背景」** Cursor 维护着独立的扩展市场，开发者可从其中安装第三方发布的扩展；这类市场渠道与 Anthropic 官方发布渠道相互独立。SSH 的 authorized_keys 文件列出被允许登录该账户的公钥，因此向该文件追加攻击者公钥，就等于为攻击者留下可远程登录的入口。
