将 NES 6502 模拟器嵌入 Qwen3.5-4B 权重 ⭐️ 7.0/10

Drew Breunig 在 Qwen3.5-4B 的权重中嵌入了一个可运行的 NES 6502 CPU 模拟器，项目 nesformer 已公开，可用于运行 Super Mario Bros 等 NES ROM，但速度很慢。它受 Divyansh Agrawal 的 qwenputer 启发，并在 Hacker News 评论中给出了用 Opus 5.5 构建该系统时使用的提示词。实现据称使用了 Christopher Pow 约 15 年前发布的 NES CPU 一致性测试集。当前缺少基准和效率细节，因此它更像“模型权重内计算”的可复现实验，而非可直接实用的方案。

rss · Simon Willison · 10月30日 21:59

「怎么用」 可以先查看 dbreunig/nesformer 仓库的代码与提示词，按其说明准备 Qwen3.5-4B 权重和 CLI，再把 ROM 指给模拟器运行。适合想研究“权重内模拟”或复现构建流程的人；材料未给出安装步骤、硬件要求和速度数据，首次尝试需以仓库文档为准，不建议把它当作日常游戏或生产工作流。

「为何现在值得看」 它把 qwenputer 的思路推进到完整的 NES CPU 模拟，并且公开了代码与构建提示词，使这类实验从演示变成可复现的样本。不过目前只有“很慢”的描述，缺少基准与效率数据，能否扩展到实用场景尚未证实。

并行跑 coding agent：先隔离机器，再谈代码 ⭐️ 6.0/10

这是一篇来自 r/ChatGPTCoding 的经验帖，作者在 Apple Silicon Mac 上同时运行多个 Codex worker，结论是并行 agent 出问题多半不在代码质量，而在共享资源：有人跑 5 个以上会话时，一个 agent 关掉了另一个正在用的模拟器；分开的文件夹并不能隔离共用的工具、浏览器和缓存。作者指出 git worktree 只保护仓库、不保护整台机器，且会不断堆积，有人在自己的 Mac 上发现过 47GB 的旧 worktree。他的做法是给每个 worker 一个独立 Linux 容器，只挂载该 worker 的工作区，不带 home 目录，浏览器与登录也各自独立，成果需主动保存才落到 Mac 上。验收标准是真实输出，例如最近一次任务返回的是实际测试结果：6 个测试通过、exit 0、55 秒。作者也说明限制：这只是单台 Apple Silicon Mac 上的经验，容器是强边界而非保证，且不解决磁盘占用，仅环境本身就要约 700MB 下载。帖子没有给出具体工具、配置、基准或成本对比。

rss · r/ChatGPTCoding · 10月30日 13:18

「怎么用」 如果你已经在同一台机器上并行跑多个 agent，并遇到过互相抢占模拟器、浏览器或缓存的情况，可以优先考虑“一 worker 一容器、只挂载工作区、不挂 home”的隔离方式，并把“任务完成”定义为可核对的实际输出（如测试通过数、退出码、耗时），而不是 agent 自己声称完成。需要注意的是，帖子只给了思路，没有给容器方案、编排方式或清理规则；作者本人也在向评论者征集任务结束后的删除与清理做法，因此照做前还需自行确定用哪套容器工具、如何回收镜像与工作区。

标签: #coding-agents, #parallel-agents, #workflow, #isolation, #containers, #agent-ops

AI 不会取代 SRE，但可能让 SRE 技能退化 ⭐️ 4.0/10

SigNoz 的一篇 newsletter 评论文章提出：与其争论 AI 是否会取代 SRE，不如关注 AI 是否在悄悄削弱 SRE 的能力。作者借用 1983 年 Lisanne Bainbridge 的《Ironies of Automation》（自动化反讽）作类比——自动化接管常规操作后，人只在罕见的高风险时刻介入，反而因缺乏练习而更不擅长处理这些时刻。文中引用了两个跨领域证据：内镜医师在使用 AI 辅助息肉检测一段时间后，无辅助检出率从 28% 降至 22%；长途飞行员过度依赖自动驾驶导致情景意识与手动飞行能力下降，FAA 因此强制要求手动飞行时长。文章还借 PagerDuty 的分级模型说明现状：Tier 1 已知问题全自动、Tier 2 AI 建议加人工确认、Tier 3 新颖复杂故障由人主导；并警告 Tier 3 恰是最需要直觉的部分，而直觉只能靠反复实操积累。此外文章提出「never-skilling」（从未习得）比 deskilling 更值得担心：初级 SRE 在 AI 主导的响应流程中缺少打基础的机会。需要说明的是，这是一篇观点文章，不是针对 SRE 的实证研究，所引研究未给出处，且原文在给出对策时被截断。

Cursor 市场出现篡改版 Claude Code 扩展并植入 SSH 公钥 ⭐️ 8.0/10

Cursor 市场上一度出现一份被篡改的 Claude Code VS Code 扩展，它会把标为 svc-telemetry 的攻击者公钥追加到用户的 ~/.ssh/authorized_keys。Anthropic 员工在讨论中表示，这不是 Anthropic 系统或员工电脑被攻破，官方渠道的版本不受影响，恶意者利用的是 Cursor 市场的发布访问权限。评论中引用的 Reuters 报道称，Cursor 表示该恶意扩展在周四约 2:27 至 13:35（PT）上线，影响范围仅限 Cursor 用户。

hackernews · _chall · 10月30日 07:09 · 社区讨论

「背景」 Cursor 维护着独立的扩展市场，开发者可从其中安装第三方发布的扩展；这类市场渠道与 Anthropic 官方发布渠道相互独立。SSH 的 authorized_keys 文件列出被允许登录该账户的公钥，因此向该文件追加攻击者公钥，就等于为攻击者留下可远程登录的入口。

「影响与处置」 对使用 Cursor 的开发者而言，最直接的处置是检查 ~/.ssh/authorized_keys 是否含 svc-telemetry 条目；若存在，应移除该公钥并审计 SSH 访问权限。

「社区讨论」 评论中的主要争议是责任归属：有用户引用 Reuters 的时间线追问这到底算不算 Anthropic 的问题，Anthropic 的 Felix 则澄清是 Cursor 市场发布权限被滥用，而非 Anthropic 系统被攻破。另有用户指出，原始 Phorion 报告详细说明了扩展写入 SSH 公钥的具体行为。
